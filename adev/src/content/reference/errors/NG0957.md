# Collection used in @for is not iterable

# @for에 사용한 컬렉션을 순회할 수 없음

<!--
A `@for` loop repeats over an array, or over a value that implements the [iterable protocol](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Iteration_protocols), such as a `Map`, a `Set` or a generator. This error means the collection was neither, most often a plain object:

```angular-ts
@Component({
  template: `@for (item of items; track item) {
    {{ item }}
  }`,
})
class Test {
  items = {first: 'a', second: 'b'};
}
```

`null` and `undefined` render nothing instead of throwing, so this error only reports a value that is present but cannot be iterated.
-->

`@for` 루프는 배열이나 `Map`, `Set`, 제너레이터 같이 [이터러블 프로토콜](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Iteration_protocols)을 구현한 값을 순회합니다.
이 오류는 전달한 값이 어느 쪽에도 해당하지 않을 때 발생합니다. 대표적인 예가 일반 객체입니다.

```angular-ts
@Component({
  template: `@for (item of items; track item) {
    {{ item }}
  }`,
})
class Test {
  items = {first: 'a', second: 'b'};
}
```

`null`과 `undefined`는 오류를 일으키지 않고 빈 컬렉션처럼 처리됩니다.
루프 본문은 렌더링되지 않으며, `@empty` 블록이 있으면 그 블록을 표시합니다.
따라서 이 오류는 값이 있지만 그 값을 순회할 수 없을 때만 발생합니다.

## Fixing the error
-->

## 오류 해결

<!--
To repeat over the entries of a plain object, use the [KeyValue pipe](/api/common/KeyValuePipe):

```angular-ts
@Component({
  imports: [KeyValuePipe],
  template: `@for (item of items | keyvalue; track item.key) {
    {{ item.key }}: {{ item.value }}
  }`,
})
class Test {
  items = {first: 'a', second: 'b'};
}
```

If the collection comes from an API call or another dynamic source, check that the value is the list itself. A response that wraps the list in another object, such as `{data: [...]}`, is a common cause.
-->

일반 객체의 항목을 순회하려면 [KeyValue 파이프](/api/common/KeyValuePipe)를 사용하세요.

```angular-ts
@Component({
  imports: [KeyValuePipe],
  template: `@for (item of items | keyvalue; track item.key) {
    {{ item.key }}: {{ item.value }}
  }`,
})
class Test {
  items = {first: 'a', second: 'b'};
}
```

API 호출이나 다른 동적 소스에서 컬렉션을 가져온다면 목록 자체가 전달되는지 확인하세요.
`{data: [...]}`와 같이 객체로 목록을 감싼 응답을 그대로 전달하면 이 오류가 발생할 수 있습니다.
