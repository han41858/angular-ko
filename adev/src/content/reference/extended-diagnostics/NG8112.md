# 사용하지 않는 `@let` 선언

<!--
This diagnostic detects `@let` declarations whose value is never read in the template.
-->

이 진단은 템플릿에서 값을 한 번도 읽지 않는 `@let` 선언을 감지합니다.

```angular-ts
import {Component} from '@angular/core';

@Component({
  template: `
    @let fullName = user.firstName + ' ' + user.lastName;
    <h1>Welcome</h1>
  `,
})
class MyComponent {
  user = {firstName: 'Ada', lastName: 'Lovelace'};
}
```

<!--
## What's wrong with that?
-->

<a id="whats-wrong-with-that"></a>

## 어떤 문제가 있나요?

<!--
An unused `@let` is usually left over from a refactor, or points to a place where the value was meant to be used.
Angular still evaluates the expression of an unused `@let` each time the template updates. For example, a function call in the expression still runs.
-->

사용하지 않는 `@let`은 보통 리팩터링 후 남은 코드이거나 원래 값을 사용하려던 위치를 나타냅니다. Angular는 템플릿을 갱신할 때마다 사용하지 않는 `@let`의 표현식도 평가합니다. 예를 들어 표현식에 함수 호출이 있으면 그 함수도 계속 실행됩니다.

<!--
## What should I do instead?
-->

<a id="what-should-i-do-instead"></a>

## 어떻게 수정해야 하나요?

<!--
Either use the declaration or remove it:
-->

선언을 사용하거나 제거하세요.

```angular-ts {prefer, header: "use the declaration"}
@Component({
  template: `
    @let fullName = user.firstName + ' ' + user.lastName;
    <h1>Welcome, {{ fullName }}</h1>
  `,
})
class MyComponent {
  user = {firstName: 'Ada', lastName: 'Lovelace'};
}
```

```angular-ts {prefer, header: "remove the declaration"}
@Component({
  template: `<h1>Welcome</h1>`,
})
class MyComponent {}
```

<!--
## What if I can't avoid this?
-->

<a id="what-if-i-cant-avoid-this"></a>

## 피할 수 없다면 어떻게 하나요?

<!--
This diagnostic can be disabled by editing the project's `tsconfig.json` file:
-->

프로젝트의 `tsconfig.json` 파일을 편집하여 이 진단을 비활성화할 수 있습니다.

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "unusedLetDeclaration": "suppress"
      }
    }
  }
}
```

See [extended diagnostic configuration](extended-diagnostics#configuration) for more info.
-->
