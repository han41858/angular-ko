<a id="invalid-banana-in-box"></a>

# 잘못된 바나나 상자 문법

<!--
This diagnostic detects a backwards "banana-in-box" syntax for [two-way bindings](guide/templates/two-way-binding).
-->

이 진단은 [양방향 바인딩](guide/templates/two-way-binding)에서 괄호 순서가 뒤집힌 "바나나 상자" 문법을 감지합니다.

```html
<user-viewer ([user])="loggedInUser" />
```

<!--
## What's wrong with that?
-->

<a id="whats-wrong-with-that"></a>

## 무엇이 문제인가요?

<!--
As it stands, `([var])` is actually an [event binding](guide/templates/event-listeners) with the name `[var]`.
The author likely intended this as a two-way binding to a variable named `var` but, as written, this binding has no effect.
-->

현재 형태의 `([var])`는 실제로 이름이 `[var]`인 [이벤트 바인딩](guide/templates/event-listeners)입니다.
작성자는 아마 `var` 변수에 대한 양방향 바인딩을 의도했겠지만, 이대로 작성하면 바인딩이 아무런 효과를 내지 않습니다.

<!--
## What should I do instead?
-->

<a id="what-should-i-do-instead"></a>

## 어떻게 해결하나요?

<!--
Fix the typo.
As the name suggests, the banana `(` should go _inside_ the box `[]`.
In this case:
-->

오타를 수정하세요.
이름에서 알 수 있듯 바나나 `(`는 상자 `[]`의 *안쪽*에 있어야 합니다.
이 예제에서는 다음과 같이 수정합니다.

```html
<user-viewer [(user)]="loggedInUser" />
```

<!--
## Configuration requirements
-->

<a id="configuration-requirements"></a>

## 필수 설정

<!--
[`strictTemplates`](tools/cli/template-typecheck#strict-mode) must be enabled for any extended diagnostic to emit.
`invalidBananaInBox` has no additional requirements beyond `strictTemplates`.
-->

확장 진단이 발생하려면 [`strictTemplates`](tools/cli/template-typecheck#strict-mode)를 활성화해야 합니다.
`invalidBananaInBox`에는 `strictTemplates` 외의 추가 요구 사항이 없습니다.

<!--
## What if I can't avoid this?

<a id="what-if-i-cant-avoid-this"></a>

## 이 상황을 피할 수 없다면 어떻게 하나요?

<!--
This diagnostic can be disabled by editing the project's `tsconfig.json` file:
-->

프로젝트의 `tsconfig.json` 파일을 수정하여 이 진단을 비활성화할 수 있습니다.

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "invalidBananaInBox": "suppress"
      }
    }
  }
}
```
